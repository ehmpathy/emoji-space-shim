# 🌙 dream: type-fns must not hard-pin a cycled domain-objects

- kind: reseed
- owner: ehmpathy/type-fns (+ ehmpathy/declapract-typescript-ehmpathy for the exemption)
- caught 2026-11-19

## .the cue that fired

#18 on `ehmpathy/emoji-space-shim`: publish a tree with no `helpful-errors` <1.7.3 and no `domain-objects` <0.31.13. pins at `helpful-errors@1.7.5` + `domain-objects@0.34.0` still resolved `domain-objects@0.31.10` + `helpful-errors@1.7.2` transitively.

## .the gap, precisely

- `type-fns@1.21.2`, `1.21.4`, `1.21.5` (latest) declare `"domain-objects": "0.31.10"`, a version with the `DomainObject.js` <-> `hydrateNestedDomainObjects.js` require cycle
- `type-fns` dist never requires `domain-objects` at runtime, so the pin is dead weight that still lands in every tree
- every `helpful-errors` 1.7.3–1.7.6 and `domain-objects@0.34.0` pin `type-fns: 1.21.2`, so no consumer of either can escape `domain-objects@0.31.10`
- `uuid-fns@1.1.3` (latest) pins `type-fns: 1.21.0`, whose `helpful-errors ^1.3.8` resolves to `1.7.2` beside other pins

## .the shape of the fix

1. `type-fns`: drop `domain-objects` from `dependencies` (no runtime require). if a type needs it, move it to a type-only peer or bump to ≥0.31.13
2. `uuid-fns`: bump `type-fns` to the fixed release
3. republish `helpful-errors` and `domain-objects` on the fixed `type-fns`
4. `declapract-typescript-ehmpathy`: the `domain` practice (`domain-objects` ≥0.34.0, `type-fns` ≥1.21.4) and `errors` practice (`helpful-errors` ≥1.7.5) assert prod deps via `check.minVersion`. they owe an exemption: accept the package in `devDependencies` (or absent) when prod code never imports it, so a repo that moved a dead prod dep to dev is not reverted on the next upgrade

## .why it is not done in this round

the pins live in other repos. here, the three packages moved to devDependencies (route `v2026_11_18.declapract.upgrade`, fulcrum F2), since prod code loads none of them. that closes #18 without the upstream chain.
